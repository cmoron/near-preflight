An AI agent cannot buy a token it could never sell.

The agent buys on the Base blockchain only through the guard, a NEAR contract. Before NEAR signs, a sentinel simulates the buy and the resale, checks whether the token's code has drained pools before, and stores a verdict anyone can replay: allow, warn (the owner decides) or block.

The agent holds no key for Base: the guard builds the transaction and NEAR Chain Signatures signs it.

What it stops

  • block listed A token you can buy but never sell
  • block listed The token's owner takes tokens back without approval
  • block A clean copy of code whose earlier pools were drained
  • block listed A token that sells only in a simulation, or at the delay a check would try
  • block A token keyed on WETH or the factory, or that fails on a later Base block
  • ignored A prompt-injected agent changes the route, recipient or minimum output: NEAR signs what was simulated

Each line opens the exact reason the sentinel gives and the test that shows it. Listed: put on the guard's shared blocklist, refused to every agent.

What it does not stop

  • A lying sentinel. Its allow on a trap can be bought within 120 s; replay shows the lie afterwards.
  • What a token does later. A pause, tax or blacklist after the buy.
  • Front-running. The signing request is public on NEAR before the swap reaches Base.
  • Other pools. Only Uniswap V2 WETH pools on Base are checked and bought today; Uniswap V3 and V4 pools are not supported yet. V2 is where copy-paste trap launches concentrate: 29 new V2 WETH pools in 2.4 h on 2026-11-11, all of one code template, 24 of them drained.

Every limit, with its reason

How one purchase goes

  1. The agent asks the guard to check a token and an amount, and pays for the check.
  2. The sentinel reads the check and simulates on Base the exact buy the guard would sign, then two sales of what it bought.
  3. It stores the verdict on the guard, with the sha256 of its evidence and the hash of the one transaction NEAR may sign.
  4. On a fresh allow, within 120 s, the agent buys. It names no route, recipient or minimum.
  5. The guard rebuilds the simulated swap and Chain Signatures signs it for the guard's Base address.
  6. A relay broadcasts the signed swap: a program that holds no key and only forwards it. In this demo, to a local fork of Base.

The guard's owner appoints the sentinel; its key can only post verdicts. What a lying sentinel can still do, and the architecture.

Verify it yourself

No NEAR account, no key: replay a stored verdict and check the model's decision behind a check. You need bun 1.4, Foundry 1.8 and jq. The README section adds the trap tests on a local fork. 

git clone https://github.com/cmoron/near-preflight && cd near-preflight && bun install
export GUARD=guard.goblin-guard-13713.testnet   # the demo guard on NEAR testnet, read only

# Check #103 (USDC on Base mainnet): resent, traced on a local fork, re-judged, compared with NEAR
bun app/replay.ts app/fixtures/usdc-base-mainnet.json https://mainnet.base.org --check
#   REPLAY OK: verdict warn confirmed, same as on chain

# The model's decision behind check #1: signature, Intel and NVIDIA attestation, the guard's record
bun app/attest.ts app/fixtures/decision.json --check 1
#   ATTEST OK: 15 checks hold (1 not verified, see SKIPPED)
